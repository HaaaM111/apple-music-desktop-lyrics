# Desktop Lyric Design

Native WPF floating overlay window (`AllowsTransparency = true`, `WindowStyle.None`, `Topmost = true`, `SizeToContent.Height`, `ResizeMode.NoResize`).

- **Typography & Rendering**: Two-track layout (`LyricsLinePresenter`) using `Segoe UI` / `Microsoft YaHei UI` fallback, ink role `#F4F4F5`, subdued next-line alpha, and single-geometry vector stroke + drop shadow (`LyricsLineLayoutEngine.MeasureVertical` snaps glyph, outline, and shadow bounds to physical pixels without `ScrollViewer`s). Long single lines shrink down to 16 DIP first, then switch to horizontal marquee when animation is enabled or ellipsis when disabled.
- **Bounds & Top-Edge Alignment**: Allowed width 420–1400 DIP (default 760 DIP), font size 16–48 DIP (default 30 DIP), auto-calculated height clamped to 96–220 DIP and constrained to `SystemParameters.WorkArea`. When docked at the work-area top edge, `AlignInkToTop` keeps first-line ink ~1 device pixel below the top edge without clipping.
- **Hover / Keyboard Chrome**: Idle window background is fully transparent (`BackgroundOpacity` defaults to 0). When unlocked, pointer hover (`LyricsOverlayHover`) or keyboard focus (`IsKeyboardFocusWithin`) reveals the translucent rounded backdrop and a detached centered `Popup` toolbar with 3 controls (`⚙`, `🔒`, `×`) placed above the overlay (flipping below when top-docked) without shifting lyric layout. Opening the settings panel immediately hides and suppresses the hover toolbar so settings always sits cleanly above the lyric overlay.
- **Click-Through Lock & Unlock**: Locking closes settings, hides the main frame/toolbar, disables edge resize handles, and enables true native mouse click-through on the main lyric window (`LyricsHitTestBridge` via `WS_EX_TRANSPARENT` and `WM_NCHITTEST -> HTTRANSPARENT`). Hovering a locked overlay reveals a clickable `🔓` button inside the detached `Popup` above/below the overlay; unlocking is also available from the system tray menu (`锁定/解锁歌词`) and `Ctrl+Alt+Shift+L`. Global hotkey registration failures are surfaced in the settings detail area.
- **Settings Panel**: Fixed `432×472` `Popup + TabControl` (`LyricsSettingsPanel`) grouped into `显示`, `歌词`, and `同步`, with independent foreground and stroke color swatches, editable HEX inputs, WinForms `ColorDialog` RGB pickers preserving alpha, current song timing status display, retry/local-import actions, and hidden reserved placeholders for future translation/romanization.
- **Persistence**: Atomic write-through JSON storage (`LyricsPreferencesStore`) to shared `work/state/settings.json` persisting window geometry, lock state, appearance settings, and per-song timing offsets (`1.5s` default lead, `±0.2s` step, `±5s` bounds). Manual startup forces visibility (`Enabled = true`) on launch without overwriting corrupt configuration files.
- **Standby & On-Demand Lifecycle**: A lightweight system-library-only watcher (`AppleMusicLyricsWatch.exe`, launched via `AppleMusicLyricsStandby.exe` or `scripts/StartStandby.ps1`) monitors `AppleMusic.exe` without loading WPF or PowerShell. When `AppleMusic.exe` starts, it launches `AppleMusicLyrics.exe --auto-launch` honoring the saved `Enabled` flag (showing immediately when `Enabled = true`, or staying hidden with tray, hotkeys, and user-SID-scoped Named Pipe IPC `HostIpc` ready when `Enabled = false`). Hiding the overlay stops the `DispatchTimer`, clears cached track state, and terminates `MediaSession.ps1` (`IMediaSourceLifecycle` + `ProcessJobGuard` kill-on-close Win32 Job Object). When all `AppleMusic.exe` processes exit, the watcher sends `CLIENT_EXITED` after debounce so the host cleanly exits back to standby while preserving `Enabled`.
